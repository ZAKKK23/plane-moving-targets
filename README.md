# plane-moving-targets

A Voronoi Tessellation Population (VTP) agent simulation with moving
targets — five target-motion variants of the same underlying model, each
with a MATLAB implementation and a dependency-light browser port.

**[Live site →](#)** (enable GitHub Pages, see below) — opens the hub page
at the repo root, which links out to each variant.

## What's shared across every variant

Agents ("cells") move under three local forces computed from their Delaunay
neighborhood:

- **repulsion** from the nearest neighboring agent
- **alignment** toward neighbors heading the same direction
- **homing** toward whichever target is currently closest

Each step is capped by an estimate of the agent's own Voronoi cell size, so a
crowded agent can never leap past its neighbors. Two constants shape that
balance and are live-editable in every variant, both on the web and in the
MATLAB control panel:

- **ν** — alignment strength (weight of the alignment force relative to
  repulsion + homing)
- **L** — interaction length scale (sets the distance at which repulsion/
  homing hand off, and caps how far a crowded agent can move per step)

What differs between variants is purely **how the targets move**.

## The five variants

| Variant | Folder | Target motion |
|---|---|---|
| Tusi couple | `variants/tulsi/` | Targets oscillate in a straight line, generated by a small circle rolling inside a fixed circle (the classical mechanism for turning two rotations into linear motion). Also includes live "cells near each target" radius/time-series charts and CSV/PNG export. |
| Rectilinear + bounce | `variants/rectilinear/` | Fixed heading and speed, bouncing elastically off the walls of a box — classic billiard-ball motion. |
| Stadium track | `variants/stadium/` | Targets ride a closed "stadium" loop — two straight sides joined by two half-circles, like a running track — spaced evenly and moving together around it. |
| Aligned: one oscillating | `variants/aligned/` | A chosen number of straight-line targets on parallel horizontal lanes, plus one additional target that oscillates in y. All targets share a single x-coordinate at every instant. |
| Aligned: multiple oscillating | `variants/aligned-inverted/` | The inverse of the above: a chosen number of independently-parametrized oscillating targets (each with its own height/amplitude/ω), plus one straight-line target. Same shared-x alignment guarantee. |

## Structure

```
index.html               hub landing page — links to all 5 variants
assets/style.css         shared site styling, used by every variant
assets/d3-delaunay.min.js  shared vendored D3-Delaunay library (ISC-licensed, see d3-delaunay.LICENSE)

variants/<name>/index.html          that variant's own about / live simulation / matlab version tabs
variants/<name>/assets/sim.js       that variant's simulation engine — force law + that variant's target motion
variants/<name>/assets/app.js       that variant's page wiring (sliders, MATLAB source viewer)
variants/<name>/assets/matlab_src.json  bundled MATLAB source for that variant's in-page code viewer
variants/<name>/matlab/             that variant's original MATLAB implementation
```

Only `sim.js`, `app.js`, `index.html`'s content, and `matlab/dynamics.m`
differ between variants — the rest of each variant's `matlab/` folder
(`Target.m`, `neighborhoods.m`, `alignTo.m`, `transition.m`,
`voronoiProjectToBoundary.m`, etc.) is the same core VTP implementation,
copied per variant so each one stays a complete, self-contained MATLAB
project you can hand someone on its own.

## Running the web version

No build step. Either open `index.html` directly, or serve the whole repo:

```
python3 -m http.server 8000
```

then visit `http://localhost:8000/` for the hub page, or
`http://localhost:8000/variants/<name>/` for a specific variant directly.

## Running a MATLAB variant

Requires base MATLAB only (`delaunayTriangulation`, `polyshape` — no extra
toolboxes):

```
cd variants/<name>/matlab
matlab -r dynamics
```

or open that variant's `matlab/dynamics.m` in the MATLAB editor and run it.
Each one will prompt for its own setup (number of targets, etc.) and then
open an interactive figure with a control panel matching what's described
on that variant's own "matlab version" tab.

## Publishing to GitHub Pages

1. Create a new GitHub repository and push this folder to it (see commands
   below).
2. In the repo, go to **Settings → Pages**.
3. Under **Build and deployment**, set **Source** to `Deploy from a branch`,
   branch `main`, folder `/ (root)`.
4. Save — the hub page will be published at
   `https://<your-username>.github.io/<repo-name>/` within a minute or two,
   with each variant reachable at
   `https://<your-username>.github.io/<repo-name>/variants/<name>/`.

```bash
cd plane-moving-targets
git init
git add .
git commit -m "Initial commit: VTP moving-targets collection (5 variants)"
git branch -M main
git remote add origin https://github.com/<your-username>/<repo-name>.git
git push -u origin main
```

## Note on the JS ports

Each variant's browser port implements the same force law as its
`dynamics.m` (repulsion + alignment + homing, weighted by the
`expReciprocal` transition function over the Delaunay graph), with the same
live-editable ν and L. One piece is approximated for simplicity in every
variant: the MATLAB version caps an agent's step by ray-casting its intended
direction onto the exact boundary of its Voronoi cell
(`voronoiProjectToBoundary.m`); the JS version approximates that cap as half
the distance to the nearest Delaunay neighbor. Visually and qualitatively
the dynamics match; if you need the exact cap, port
`voronoiProjectToBoundary.m` into the relevant `sim.js`.
